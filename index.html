Household first, community only as overflow

Abstract

A household MeshStack pools devices under one principal. The frozen file used by the v2 reference, Qwen3.6-27B-Q4_0, is 15,791,278,304 bytes. The 2/4/6 GB class floors advertise 12,884,901,888 bytes together. The weights exceed that aggregate before KV, workspace, or the reserve floor. This specification defines the overflow and nothing else: authenticated subscribers may place a frozen model on hardware other principals have opted in, under a grant bound to principal, lease epoch, and model fingerprint. Whole-request on hardware the subscriber already holds is preferred and spends zero community credits. Foreground work is excluded. Credits do not transfer.

The audit record is a permissioned hash chain of metadata. It is not a cryptocurrency, not a consensus protocol, and not on the decode path. Under an assumed commit round trip of 40 ms, committing on every token or every hop of a 3-stage, 256-token loop adds 10.24 s or 20.48 s inside the loop. The specification adds 0 ms by construction. Revocation poisons the session locally. The block records the revocation after the fact.

Decision D23 is the admission code of record. The inequality printed in the household report is a different predicate. On this geometry the two disagree at context 4096 for one 32 GB host, two 16 GB hosts, and two 32 GB hosts, and the disagreement widens at context 32768, where a 64 GB host that whole-requests at 4096 becomes unplaceable under D23 (3 layers left) while the printed cross-check still whole-requests it. The first stage of a three-host 16 GB pipeline at context 4096 is admitted with 8,902,528 bytes of slack. That is a packing result, not a performance result. No device measurement, no tokens per second, and no production community mesh are claimed.

1. The file does not fit

The problem is arithmetic. Usable RAM is 60 percent of advertised RAM, decision of record, not a measurement of a particular operating system. On the household floors the planner still seats a prefix and then stops. At context 4096 the 2/4/6 GB floors leave 43 layers unplaced under D23. An 8 GB endpoint alone leaves 49 layers. Sending the prompt to a hosted API would spend money per token and would leave the principal. This paper does not price that API. It asks whether idle memory the subscriber can already see, under a grant, can hold the layers the household cannot.

Pipeline parallelism is the mesh form (D10, 2026-10-30). Tensor parallelism stays intra-node. A community spill is therefore a chain of contiguous layer spans, not a slice of one matrix across houses. One span on one node is whole-request and has zero activation hops. Every extra stage adds a hop on every token. The planner takes the longest span each admitted node can hold, largest usable RAM first, and stops when the layers are covered. Extra hosts that are not needed do not get a stage. At context 4096, four 16 GB hosts and six 16 GB hosts both plan as three stages, because three already cover the model.

2. The product decision

Overflow does not replace the products. The order is fixed.

  1. If one node the principal holds can whole-request the frozen model, run it there. Community spend is zero.
  2. If that node is in the foreground, it is out of the pool for that interval. Owner work wins.
  3. If the model is unplaceable at home, a grant may reserve opted-in hosts. The reservation is one credit per stage, and one credit is one usable GiB-hour. That is a stated constant, not a price and not a coin.
  4. If the planner returns unplaceable, there is no placement block. The session does not start on a partial model.
  5. A small endpoint keeps the grant and the prompt. It does not grow into a datacenter, and it does not call a public API to hide the miss.

On the frozen model at context 4096 an idle 128 GB key, the stated product capacity and not a fresh measurement of bytes left after the operating system, whole-requests every layer at 0 community milli-credits and earns 76.8 credits in an idle hour. That hour covers 25 three-stage spills. The same key held at owner priority drops out, and three 16 GB desks pipeline the model at 3 credits. An 8 GB endpoint cannot do this alone. The desks can. A grant of 8 credits covers 2 such spills and leaves 2.

3. Decisions inherited, not re-litigated

Community overflow does not get its own planner. It calls the planner of record and then refuses to put the receipt on the hot path. The following entries in DECISIONS.md of ttracx/thox-meshstack-inference are constraints on this specification. Dates are the decision dates. This paper does not amend them.

4. The four-times KV error

Before D22 the preset counted KV on all 64 layers. The verified geometry has 16 full-attention layers, 4 KV heads, head dimension 256, fp16. Correct bytes per token are 2 × 16 × 4 × 256 × 2 = 65,536. The old formula is 262,144, a factor of 4. At context 4096 that is 0.250 GiB versus 1.000 GiB. The missing recurrent state, 48 layers × 128 × 6144 × 4, is 150,994,944 bytes (0.141 GiB). D22 records that figure as an fp32 estimate from GGUF metadata, not a measured llama.cpp buffer. This paper does not promote it to a measurement.

The activation that crosses a stage boundary, if carried as fp32 at the hidden size 5120, is 20,480 bytes per token. D34 cites that derivation (about 20,480 bytes) and concludes that decode is not the bandwidth problem; prefill chunks and KV movement are. We adopt the byte count as calculated. We do not adopt a throughput.

5. Admission, worked in bytes

For a node with advertised memory M and a contiguous layer span, the code of record is:

U     = floor(0.6 · M)
ρ     = ceil(0.25 · U)
R     = W(span) + K(span) + C(span) + max(0, ρ − K(span))
S     = layers(span) · hidden · context · 4
admit iff R ≤ U and S ≤ U_sys
U_sys defaults to U when no separate system RAM is declared

W, K, and C use the cumulative floor split from the v2 planner, so adjacent spans do not drop or double a byte of the frozen file. Candidates must be alive, opted in, thermally accepted, and not in owner-foreground state. The printed household statement was W(s) + K(s)·T ≤ R(n) and WS(s) ≤ Σ(n), domains not summed, and it did not put this reserve floor inside R. Section 6 keeps both predicates. D23 decides whether a block may exist.

Three opted-in 16 GB hosts, context 4096. Usable RAM on each host is 10,307,921,510 bytes (9.600 GiB). The binary search seats 31, 31, and 2 layers. The first stage clears the usable-RAM test by 8,902,528 bytes. One more layer on that host fails. The third host is almost empty because the model has already been covered, not because the planner is balancing load. There is no load-balance claim.

8. Why a coin on the token path fails

A hash chain can record who reserved memory. It cannot be a precondition of the next token. Let N be generated tokens, H the number of activation hops, R an assumed commit round trip. H = max(0, stages − 1). Added delay inside the token loop is 0 if settlement is off the path, N·R if every token waits for a commit, and N·H·R if every hop waits for a commit. For the fixture N = 256, stages = 3, H = 2, R = 40 ms, those rejected designs add 10,240 ms and 20,480 ms. The specification adds 0 ms. R is not a measured round trip on a THOX link. Changing R changes only the rejected column.

Settlement may batch. The fixture batches every 64 tokens, which is 4 batches in a 256-token run, and the batch lags by one assumed round trip beside the loop. Auditors recompute the chain later. That work is not time-to-token. Certificate Transparency (RFC 6962) is the pattern for an asynchronous audit log. It is not implemented here. There is no gossip, no mempool, no gas, and no Byzantine quorum. The sequencer is the coordinator. It can omit a metadata block. Recomputing hashes detects a rewrite of a block that is still present. It does not detect the omission.

9. Ledger, grants, credits

The laboratory chain is SHA-256 of the previous hash and a canonical JSON body. Legal types are genesis, enroll, advertise, earn, endow, reserve, placement, grant, settle, and revoke. A transfer type is defined only so it can be rejected. Field names prompt, prompts, activation, activations, kv, weights, payload, plaintext, tokens, and embedding are rejected before append. Credits are non-transferable. A reservation id cannot be spent twice. A repeated transaction id is a replay. After revoke, the epoch increments and a settlement carrying the old epoch is refused.

The fixture on the three-stage plan appends 16 blocks, the chain verifies, a one-field tamper of block 1 fails the hash at index 1, and payload bytes committed are 0. Subscriber remainder after the 3-credit reservation against an 8-credit endowment is 5 credits. Those balances are milli-credits in the ledger state (8000 endowed, 3000 reserved, 5000 left, epoch 2, revoked). Replay, double-spend, credit transfer, a prompt field, and a late settlement are refused and do not become blocks. The grant drill passes.

A grant carries principal, epoch, scope, fingerprint, and parent. Consumption walks the parents. A cycle, a dead ancestor, a stale epoch, a different principal, or a different fingerprint is a rejection. Revocation clears the live bit of the root and of its children. That bit is the laboratory stand-in for deleting key material. The chain stores the revocation, not the key. The drill accepts one live KV grant and rejects the four bad presentations plus both descendants after the shred. It is a protocol drill. It is not a penetration test and not the production secrets graph.

One credit equals one usable GiB-hour offered. 1 MeshCredit per usable GiB-hour offered. Stated constant, not a fitted price. The community-pool sketch offers 134.4 usable GiB and therefore 134.4 credits in one hour. That identity does not set a dollar price, a market, or a payout.

10. What the simulations show

Churn is an independent Bernoulli leave of each opted-in contributor, seed 20261110, 200 trials. It does not model latency, partial stage failure, or bandwidth. On the full pool at leave probability 0.2, 200 of 200 place, of which 159 are whole-request and 41 are pipelines. Histogram {"1":159,"2":38,"3":3}. The 64 GB host is why whole-request dominates: when it stays up, it takes the model.

Remove that host and the same seed places 200 of 200, whole-request 0, pipeline 200. Histogram {"2":188,"3":12}. Six 16 GB hosts at leave probability 0.35 place 182, pipeline 182, and the rest are unplaceable. Histogram {"3":182,"unplaceable":18}. A pool that only looks reliable because one large host is usually present is not a reliability result. The laboratory exposes the leave probability so that reading can be repeated rather than quoted.

11. Security requirements

The threat model is narrow. Contributors are honest-but-curious and may return with a stale lease. A subscriber may replay, double-spend, transfer credits, or try to write a prompt into a block. The coordinator is honest-but-curious about metadata and is never given the payload. There is no attestation and no enclave. Execution confidentiality is not claimed. Petals states the reason in its own paper: peers who serve the first layers can recover input tokens. A subscriber who places the first stage on someone else’s machine has shown that machine the activations. The grant does not undo that. The honest mitigation in this design is to keep the first stage at home when the first stage fits, and to say so when it does not.

CVE-2026-105192, disclosed 7 October 2026 by Yuval Moravchick of JFrog, CVSS 3.1 base 9.8. LMCache multiprocess mode opened an unauthenticated ZeroMQ ROUTER. Extension code on that socket reached pickle.loads while the server was still decoding arguments, before the handler. Affected releases are 0.3.9 through 0.5.5. The 0.5.6 fix, published 14 October 2026, replaces pickle with versioned typed MessagePack, validates the descriptor first, and chooses the wrapper from a fixed local allowlist. The default bind is localhost; a routable bind is what makes the bug a network bug. The lesson we adopt is the shape of the fix. We do not claim our laboratory was penetration-tested, and we do not claim a THOX process was vulnerable to this CVE.

Conclusion

The household already fails closed when the model does not fit, and it already keeps the coordinator off the payload. Community overflow is other principals’ idle memory, under a grant, with a receipt that cannot see the prompt and cannot sit on the token. The planner that decides whether the receipt may exist is D23, including where it is stricter than the inequality printed in the household report, and including where a longer context removes a whole-request that a short context allowed. The latency cost of the receipt, inside the token loop, is zero by construction. Making that zero true on named devices is future measurement. Until then the claim is the architecture, the calculated placements, and the refusals.
